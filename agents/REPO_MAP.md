## Как устроена работа

Два чата не пишут друг другу. Обмен только через git и `agent-handoff/`.

- **Dev** (локально) пишет код. Тяжёлое обучение локально не запускает.
- **Runner** (Runpod) выполняет команды из `request.md` и кладёт цифры в `report.md`.
- Протокол: `agents/HANDOFF_FORMAT.md`. Операции: `agents/DEV.md`, `agents/RUNNER.md`.
- Числа экспериментов бери из `report.md` и из `Articles/notes/research/Сводная_таблица_экспериментов.md`. Не выдумывай метрики.

## Протокол данных

Paper-выборка: 61 тикер, окна около 98k / 12k / 12k.

| Кусок | Интервал |
| :--- | :--- |
| Train | 2015-01-01 .. 2021-12-31 |
| Val | 2022 |
| Test | 2023 |

Окно \(T=60\), горизонт \(H=7\), длина патча 12. Шаг патча бывает 6 или 12: это разные эксперименты, их нельзя складывать в одну таблицу без пометки. Нормализация селективная: цены по окну, осцилляторы в \([-1, 1]\), волатильность по train. Пропуски цен UNH и VZ в отчётах ожидаемы.

Батч, который видит модель:

| Тензор | Смысл |
| :--- | :--- |
| `x` | эндогенные каналы, `[B, 60, F]`, \(F \in \{1, 2, 5\}\) |
| `text`, `text_seq` | компактный текст 15D: 5D FinBERT + 10D событийных прототипов |
| `ts` | 25 индикаторов TreeSHAP, `[B, 60, 25]`, только если датасет `features_mode=dual_ts` |

Датасеты:

| Конфиг | Зачем |
| :--- | :--- |
| `data=fnspid` | ранний протокол, текст 768D FinLang |
| `data=fnspid_compact` | OHLCV + текст 15D |
| `data=fnspid_selective` | селективный RevIN |
| `data=fnspid_dual_ts` | цены выбранных каналов + `ts` из сигнатуры `cache/selected_signatures/paper_fold1_signature.json` |
| `data=fnspid_selected` | все отобранные колонки одним тензором, без отдельного `ts` |

Ключ `model.d_ff` должен быть объявлен в yaml модели. У `c1_dual` это `null`: тогда ширина FFN равна `4 * d_model`. Новый ключ Hydra без поля в конфиге не примет.

## Модели

Имя в таблице — значение `model=...`. Класс регистрируется в `build_model`.

| `model=` | Класс | Что это |
| :--- | :--- | :--- |
| `dlinear` | `DLinear` | линейный бейзлайн, около 854 параметров |
| `timexer_plain` | `TimeXerPlain` | TimeXer без текста |
| `a` | `TimeXLModelA` | 1D-CNN, прототипы, позднее слияние, текст 768D |
| `b` | `TimeXerB` | TimeXer, прототипы, позднее слияние |
| `c0` | `TimeXerC0` | текст прибавляется к патчам без внимания |
| `c1` | `TimeXerC1` | текст 768D через токен \(G_{en}\) |
| `c1_compact` | `TimeXerC1Compact` | 5 OHLCV + текст 15D |
| `timexer_selected` | `TimeXerSelected` | `close` и 25 индикаторов в одном PatchEmbed |
| `c1_dual` | `TimeXerDual` | патчи цены + rFFT; \(G_{ts}\) читает индикаторы, \(G_{text}\) читает текст; токены друг друга не видят |
| `c1_hierarchical` | `TimeXerHierarchical` | ровно 2 слоя: слой 1 только \(G_{ts}\), слой 2 только \(G_{text}\) |
| `c1_factored` | `TimeXerFactored` | три проектора патча: OHLCV, индикаторы, rFFT |
| `c1_inverted` | `TimeXerInverted` | цена всё ещё патчами; 25 индикаторов — токены целого окна |
| `c1_late_fusion` | `TimeXerLateFusion` | энкодер цены и текста, 25 индикаторов прибавляются MLP в конце |

Общие детали, которые легко перепутать:

- Прототипы TimeXL считаются по ценовым сегментам до инъекции. `ModelOutput.segments` — эти сегменты. Индикаторы и текст в прототипы не входят. Файлы: `src/models/timexl_integration.py`, `src/explain/bank.py`.
- rFFT сейчас локальный: 6 логарифмов амплитуд по патчу `close`, `src/models/fft_patch.py`.
- Голова по умолчанию берёт последний патч, `src/models/head.py`, `pool=last`.
- В `c1_dual` и `c1_hierarchical` при `n_ts_features=25` тензор `ts` обязателен. Инициализация банка прототипов тоже должна его передавать.

## Что уже известно по paper

Ориентир, который трансформеры пока не обошли: **DLinear F1, test MSE \(0.7535 \pm 0.0009\)**. DLinear F5: \(0.7547 \pm 0.0028\).

Сильные ячейки октября 2026, все без прототипов, если не сказано иное:

| Модель | Протокол | Test MSE |
| :--- | :--- | :--- |
| `c1_late_fusion`, \(e=2\) | OHLCV + 25 TS, stride 6 | \(0.7577 \pm 0.0019\) |
| `c1_factored`, \(e=1\) | тот же stride 6 | \(0.7600 \pm 0.0026\) |
| `c1_dual` F2, \(e=1\) | `[close, volume]` + 25 TS, stride 12 | \(0.7655 \pm 0.0032\) |
| `c1_hierarchical` | тот же F2, два специализированных слоя | \(0.7655 \pm 0.0021\) |

Прототипы обычно снижают валидацию и не снижают тест. Второй слой помогает late fusion и не помогает dual, factored и inverted. Ужатие ширины dual и hierarchical до 75% и 50% параметров остаётся внутри шума полного размера и DLinear не приближает.
